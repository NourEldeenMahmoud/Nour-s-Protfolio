# Living Systems Lab

## Thesis

The portfolio behaves like a living engineering lab. Projects are not cards; they are systems under observation. Visitors see requests enter, services coordinate, data move, decisions branch, and outcomes appear.

## Visual Language

- Dark technical canvas with warm project-specific accents.
- Fine grids, traces, nodes, layers, logs, and annotated diagrams.
- Large editorial typography prevents the interface from becoming a dashboard.
- UI panels appear only when they carry real project evidence.

## Signature Moments

- The hero starts with a problem statement; system nodes assemble around Nour’s role.
- Audience selection reroutes the same data flow toward role proof, business outcomes, or technical depth.
- Case-study diagrams animate only the workflow currently being explained.
- Bookify can visualize search, availability, booking, payment, confirmation, and administration as one connected flow.

## Motion

- Lines travel between layers to show cause and effect.
- Architecture expands from a simple overview into deeper detail.
- Scroll advances a system state instead of moving decorative objects.
- Reduced and mobile versions use stepped diagrams or short videos.

## Typography and Color

- Expressive grotesk or engineered sans for headlines.
- Highly readable sans for narrative text.
- Monospace only for labels, logs, identifiers, and code.
- Each project gets one accent derived from its domain; avoid universal neon cyan.

## Audience Adaptation

- Recruiter: highlights responsibilities and skills at each system boundary.
- Client: highlights pain, process, and outcome.
- Developer: exposes architecture, tradeoffs, and validation.

## Risks

- Too many panels can resemble a SaaS dashboard.
- Decorative diagrams can falsely imply architecture.
- Requires verified system models for each featured project.

## Fit

Strongest direct match for “solutions, not code” and .NET/backend specialization.
