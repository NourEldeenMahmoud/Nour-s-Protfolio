# 1.3 تنفيذ الـHero في الكود

الـHero موجود داخل `Banner.tsx`.

## البنية

- `section` كاملة الارتفاع باستخدام `100svh`.
- عنوان ضخم بـAnton.
- وصف بـRoboto Flex.
- CTA.
- الأرقام مثبتة قرب الجانب الأيمن على Desktop.
- سهم حركي منفصل.
- العناصر تحمل Class مشتركة:
  - `.slide-up-and-fade`

## الحركة

عند التمرير وخروج الـHero:

- العنوان.
- الوصف.
- الزر.
- الإحصائيات.

تتحرك لأعلى `-150px` وتختفي تدريجيًا.

الـScrollTrigger:

```text
start: bottom 70%
end: bottom 10%
scrub: 1
```

## لماذا الحركة جيدة؟

- لا تمنع قراءة الـHero.
- تحدث عند مغادرة القسم، لا أثناء دخوله.
- تجعل الانتقال للقسم التالي طبيعيًا.
- تستخدم Transform وOpacity، وهما أفضل نسبيًا للأداء.

## المشكلات

### Selector عام داخل Scope

استخدام `.slide-up-and-fade` مقبول بسبب GSAP scope، لكنه يظل مبنيًا على Classes وليس Refs صريحة.

### لا يوجد Reduced Motion

الكود لا يتحقق من:

```css
prefers-reduced-motion
```

### عناصر كثيرة تتحرك بنفس النمط

العنوان والوصف والزر والأرقام تتحرك كلها للأعلى. هذا منظم، لكنه لا يصنع Hierarchy حركية مميزة.

# 1.4 مقدمة التحميل Preloader

الموقع يستخدم Preloader باسم `MAGED`.

## التنفيذ

- عشرة أعمدة سوداء، عرض كل واحد 10%.
- الاسم يظهر بحروف منفصلة.
- الحروف تدخل لأعلى.
- Delay يقارب ثانية.
- الأعمدة تنزلق إلى الأسفل.
- الـPreloader يختفي.

## نقاط القوة

- بسيط.
- مرتبط بالاسم.
- لا يحتاج فيديو.
- تنفيذه خفيف نسبيًا مقارنة بـ3D loader.
- يعطي إحساسًا احترافيًا.

## نقاط الضعف

### يظهر على كل تحميل

المكون موجود داخل Root Layout، ما قد يؤدي إلى ظهوره في كل زيارة أو Refresh، وربما أثناء بعض حالات التنقل حسب سلوك App Router.

### لا يعكس تحميلًا حقيقيًا

هو Intro زمني، وليس Load progress حقيقيًا.

### لا يوجد Skip

لا توجد وسيلة واضحة للتخطي.

### لا يوجد Reduced Motion

المستخدم الذي يطلب تقليل الحركة سيظل يرى العرض.

### يغطي المحتوى بالكامل

حتى لو كان HTML جاهزًا، الـPreloader يخفيه بصريًا لفترة.

## القرار المناسب لـNour

لا نأخذ Preloader كامل.

يمكن استخدام:

- Intro أقل من 1.5 ثانية.
- مرة واحدة في الجلسة.
- قابل للتخطي.
- لا يمنع الوصول إلى Skip link.
- Reduced motion يعرض المحتوى فورًا.

# 1.10 حركة سهم المشروع

عند Hover:

- حدود المربع تُرسم.
- خط السهم يُرسم.
- انحناءة السهم تُرسم.
- الأيقونة تختفي.
- Timeline يتكرر بلا نهاية مع Repeat delay.

## ما يعمل

- Microinteraction دقيقة.
- مرتبطة بفعل فتح التفاصيل.
- رسم SVG أخف من Animation مصورة.

## المشكلة

Timeline يبدأ بـ:

```text
repeat: -1
```

أي يستمر حتى Mouse leave.

هذا زائد نسبيًا؛ لأن المستخدم فهم الإشارة من أول دورة.

الأفضل:

- دورة واحدة.
- أو Repeat مرة واحدة فقط.
- أو إيقاف بعد اكتمال الرسم.

## ملاحظة Code Quality

`context.kill()` عند Mouse leave قد يقتل GSAP context الأوسع المرتبط بالمكون، وليس Timeline واحدة فقط. التنفيذ يحتاج مراجعة حتى لا يؤثر في إعادة دخول Hover أو Cleanup.

### HTML داخل Strings

```text

```

هذا يسبب:

- صعوبة Localization.

- خلط Content وMarkup.
- صعوبة إعادة ترتيب الحقول.
- صعوبة استخراج Summary للـRecruiter.
- خطورة محتملة إذا أصبح المحتوى خارجيًا مستقبلًا.

### Emoji داخل المحتوى

الإيموجي داخل القوائم يعطي وضوحًا سريعًا، لكنه قد يجعل Case Study تبدو أقل احترافية، خصوصًا عند كل Bullet.

## البديل

```ts
type Project = {
  problem: LocalizedText;
  context: ProjectContext;
  role: LocalizedText;
  features: LocalizedBullet[];
  decisions: Decision[];
  evidence: Evidence[];
};
```
